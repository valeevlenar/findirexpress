# FindirExpress

FindirExpress ведёт финансовую отчётность для компаний, торгующих на Wildberries. Три Telegram-бота (основной, административный и поддержки) запускаются из `main.py` вместе с APScheduler. Хранилище — PostgreSQL через асинхронный SQLAlchemy.

## Где смотреть код

- `app/scheduler.py` — реально включённые задания и их расписание. Основной цикл отчётности запускается одним активным триггером.
- `app/app_logic.py` — загрузка данных и формирование отчётов по продавцам. `app/get_data/` — интеграции WB, `app/database/apirequests.py` — общий клиент с обработкой лимитов и повторов.
- `app/database/sales_report_compilation.py` — сборка финансовых данных и распределение расходов. `app/reports/` — недельные и месячные отчёты, налоговый отчёт и остатки.
- `app/get_data/wbrequests.py` — адаптер действующего финансового API в формат внутренней модели отчёта. Остатки загружаются через Warehouse Remains в `app/get_data/get_stocks.py`.
- `CLAUDE.md` — подробная карта модулей. При расхождениях сверяйся с кодом и расписанием. Интеграция банка «Точка» опциональна.
- В отчётах WB могут приходить агрегаты `Склад WB РФ` и `Склад WB СГТ РФ`. Для планирования поставок используй данные о доступных складах из API поставок FBW. Агрегаты отражают суммарные остатки или расходы.

## Эксплуатация

Продакшен работает в Docker Compose. Прикладные журналы `info.log` и `finbot_log.log` находятся в рабочем каталоге контейнера. Настройки берутся из `.env`, пример переменных — `.env.example`. Изменения типов существующих колонок применяются отдельно от запуска приложения, см. `migrations/`.

Дополнительные отчёты и расчёты поставок развиваются в ветке `codex/seller-tools`. Проверку ботов и новых заданий выполняй с отдельной конфигурацией, поскольку Telegram polling и планировщик запускаются в одном процессе. См. `docs/codex-onboarding.md`.
